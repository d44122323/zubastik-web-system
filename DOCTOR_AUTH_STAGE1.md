# Этап 1 — авторизация врача

Добавлена отдельная авторизация врача без изменения существующего входа администратора.

## URL

- Администратор: `/login.html`
- Врач: `/doctor/login.html`
- Кабинет врача: `/doctor-dashboard.html`

## Demo accounts

При первом запуске для врачей 1–7 создаются учётные записи, если для врача ещё нет пользователя:

- `doctor1` / `Doctor1!2026`
- `doctor2` / `Doctor2!2026`
- ...
- `doctor7` / `Doctor7!2026`

Это только локальные демонстрационные пароли. Перед реальным использованием их нужно заменить.

## Архитектура

Созданы таблицы `users` и `auth_sessions`.

`users.doctor_id` связывает учётную запись с конкретным врачом.

Пароли не хранятся в открытом виде: используется PBKDF2-HMAC-SHA256 с солью.

Сессия врача хранится в БД и передаётся через HttpOnly cookie `doctor_session`.

Backend endpoint `/api/doctor/me` всегда получает врача из серверной сессии. В следующих этапах этот же механизм используется для фильтрации заявок и пациентов по `doctor_id`.

Существующий `admins` и `/admin/login` не изменены.
